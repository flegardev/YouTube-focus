## Launch checklist

- Confirm exact existing Store item, account and manifest version. Logger identity is unresolved.
- Rebuild from the reviewed commit; compare canonical package hashes, permissions and packaged assets.
- Pass CI, real extension journeys and upgrade fixtures; resolve significant visual/security findings.
- Review actual Store screenshots at upload dimensions. Mark sample data clearly; never invent user counts or testimonials.
- Recheck current Store single-purpose/privacy requirements and disclosures before submission.
- Validate current live site behavior where access permits. Do not bypass access controls.
- Run the five-person usability script and address primary-flow confusion.
- Upload to the existing item, then record upload, submission, review and publication as separate states.
- Verify the published package/version independently after approval.

## Ethical feedback

Use GitHub issues for reproducible technical reports and voluntary qualitative feedback. Ask users to redact personal information. Do not post launch announcements, solicit reviews or message communities automatically. Do not buy reviews, gate functionality on ratings or reward positive ratings.

## Measurement without invasive analytics

Use Store aggregate listing impressions and installs when available to estimate conversion. Track aggregate support themes, reproducible regressions and voluntary satisfaction responses. Onboarding completion and repeat usage are proposed metrics only: no telemetry was added, so they are not currently measured centrally. A consented pilot can collect participant-reported repeat use and task completion. Do not send browsing history or vehicle notes to measure growth.

## Distribution decisions

Start with the existing Store and repository documentation. A separate hosted landing page adds maintenance before product validation; defer it until the screenshots, user study and Store release are ready. No new paid service, account, backend or analytics dependency is required.

## Future opportunities, not delivered claims

Garage: verified live access, a richer maintenance planner and explicit cost assumptions. YouTube: broader live-layout regression coverage and preset export. Logger: historical category correction with explicit recalculation semantics, a richer activity timeline and full large-history browser profiling. Prioritize evidence from users over adding all of these.
